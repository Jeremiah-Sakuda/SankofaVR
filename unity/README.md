# Unity application

**Status — October 4, 2026:** the first full slice, built and tested in software with the draft [Enkare Nairobi](../docs/content/enkare-nairobi/README.md) story package and its pre-rendered narration. It has not run on a headset, in the Meta XR Simulator with hands, or with a participant. The stories are not yet reviewed by family or community.

| Item | Version or choice |
|---|---|
| Editor | Unity 6000.3.25f1 (6.3 LTS), the version the previous Nafasi project used with Meta XR Core 207 |
| Meta XR | `com.meta.xr.sdk.core` 207.0.0 from Meta's npm registry (scoped registry in `Packages/manifest.json`) |
| XR runtime | Unity OpenXR 1.18.0 with the Meta Quest, Meta XR and hand interaction features; single-pass instanced (multiview) |
| Rendering | Built-in pipeline, Vulkan, linear colour. Surfaces are lit analytically by one warm source (no Unity lights) |
| Input | Hands first, through Meta's OpenXR hand skeleton: touch, open palm and fingertip presses, or point and pinch at a panel. Touch controllers are optional (point and pull the trigger). Passthrough off: full VR is the baseline |
| Application id | `com.sankofa.quest`, provisional. A store release channel fixes it permanently; confirm before the first upload |

## Layout

```text
Assets/Sankofa/Core/         Story core: packages, plan composition and validation, story run, visit journal, kept visits (engine-free)
Assets/Sankofa/Flow/         Application flow: visit phases, choices, questions, keep/replay/continue/forget, cues, timing (engine-free)
Assets/Sankofa/Interaction/  Gesture logic: poke, open-palm receive, touch and head-direction attention (engine-free)
Assets/Sankofa/Storage/      Kept visits on the device: one JSON file, written atomically (engine-free)
Assets/Sankofa/Runtime/      Presentation and input: fire, narration, captions, panels, stage, transition, ambience, composition
Assets/Sankofa/Editor/       Project setup, scene generation, narration import, build, simulator launcher and build guards
Assets/Sankofa/Content/      The Enkare Nairobi story package and its narration manifest
Assets/Sankofa/Resources/Narration/  The griot's pre-rendered lines (MP3, imported as compressed mono)
Assets/Sankofa/Art/          Stereo-safe shaders and generated materials, meshes and noise
Assets/Sankofa/Scenes/       Hearth.unity, generated by SankofaSceneBuilder
Assets/Sankofa/Tests/        EditMode and PlayMode tests
Assets/Oculus, Assets/XR, Assets/Resources, Assets/Plugins/Android
                             Meta, OpenXR and manifest settings maintained by the tools
```

The engine-free folders are also compiled and tested outside Unity by [../dotnet](../dotnet). Unity enforces their dependency direction through assembly definitions: the core references nothing, the flow references only the core, and nothing engine-free references Unity.

`Hearth.unity` and the materials and meshes in `Art/Generated` are produced by code. Change `SankofaSceneBuilder`, `SankofaWaterScenes` or `SankofaArt` and regenerate rather than editing them by hand.

## Commands

From the repository root, with the editor installed through Unity Hub and a signed-in, licensed Unity account:

```sh
UNITY="/Applications/Unity/Hub/Editor/6000.3.25f1/Unity.app/Contents/MacOS/Unity"
"$UNITY" -batchmode -quit -projectPath "$PWD/unity" -buildTarget Android -executeMethod Sankofa.EditorTools.SankofaProjectSetup.Configure
"$UNITY" -batchmode -quit -projectPath "$PWD/unity" -buildTarget Android -executeMethod Sankofa.EditorTools.SankofaSceneBuilder.BuildScenes
"$UNITY" -batchmode -projectPath "$PWD/unity" -buildTarget Android -runTests -testPlatform EditMode -assemblyNames Sankofa.Tests.Editor -testResults "$PWD/artifacts/logs/editmode.xml"
"$UNITY" -batchmode -quit -projectPath "$PWD/unity" -buildTarget Android -executeMethod Sankofa.EditorTools.SankofaBuild.BuildMain
```

The same actions are in the editor's **Sankofa** menu. The APK is written to the ignored `artifacts/` folder. TextMeshPro's essential resources are committed under `Assets/TextMesh Pro` (without its emoji sprites). If they are ever missing, Unity's `-importPackage` option imports them synchronously; `AssetDatabase.ImportPackage` alone completes too late in batch mode:

```sh
"$UNITY" -batchmode -quit -projectPath "$PWD/unity" -importPackage "$PWD/unity/Library/PackageCache/$(ls unity/Library/PackageCache | grep com.unity.ugui@)/Package Resources/TMP Essential Resources.unitypackage"
```

A build includes only the hearth scene; the local competition brief and references live outside `Assets`.

Every player build, from any menu or script, fails if it would ship anything from `Assets/LocalOnly`, files in `Assets/StreamingAssets`, or stale run files that Unity's performance-test package can leave in `Assets/Resources` after batch test runs; the build command deletes those first. After the build, the APK is scanned to confirm Meta's development credentials were removed.

## Narration

The griot's lines are generated ahead of time from the package, so a build never calls a service to speak. With the gcloud CLI signed in to an account that can use Cloud Text-to-Speech on the Sankofa Google Cloud project, and `ffmpeg` installed:

```sh
python3 scripts/generate_narration.py unity/Assets/Sankofa/Content/enkare-nairobi.json
```

The script renders each line with Gemini 3.1 Flash TTS (voice Kore, the original griot direction). It writes `Resources/Narration/enkare-nairobi/<line>.mp3` and records each line's clip and length in the package. Unchanged lines are skipped by fingerprint. A line the provider refuses is reported, and the script exits non-zero. Rerun it to retry. Regenerate the scenes afterwards so the stage matches the package.

## Tests

The EditMode tests check that every component is wired, that the staged objects and scenes match the bundled package, that controls and resting places are within seated reach, that hands draw over the transition curtain, that the build guards work and that the engine-free core runs under Unity's runtime.

PlayMode tests run the real scene with its narration, muted, without a headset. The first visit goes before the railway, takes the gourd, asks a question, touches, keeps the visit, follows it to today, and replays it exactly. The second is a passive visit when the railway came. The third returns early from a story. Any Sankofa error fails the test. It drives the flow directly, so it is software integration evidence, not simulator or device evidence. With `SANKOFA_CAPTURE=1` the same suite also renders review frames from the seated eye into `artifacts/captures/`. It also writes 30-second mono mixdowns of the ambience at the hearth and in each story scene, as heard from the seat (distance falloff, no spatialisation, no narration). These are desktop renders and a desktop mix, not Quest visuals or headset audio:

```sh
"$UNITY" -batchmode -projectPath "$PWD/unity" -buildTarget Android -runTests -testPlatform PlayMode -testResults "$PWD/artifacts/logs/playmode.xml"
SANKOFA_CAPTURE=1 "$UNITY" -batchmode -projectPath "$PWD/unity" -buildTarget Android -runTests -testPlatform PlayMode -testFilter Sankofa.Tests.HearthCaptures -testResults "$PWD/artifacts/logs/captures.xml"
```

## What the slice does

- **Start.** A title card over the fire names the experience and the place and says how to choose. The fire burns and the night sounds play, but nothing is spoken until **Begin** (or **Leave**).
- **Choosing.** Every button can be pressed with a fingertip, or from the seat by pointing and pinching. With Touch controllers, point and pull the trigger. A select lands when the pinch or trigger is released over the same button, so sweeping across buttons presses nothing. In the editor with no headset, the mouse points.
- **Welcome.** The fire speaks: "Come. Sit with me." It then asks when to go: *Before the railway* or *When the railway came*. The visitor can choose during the welcome. Without input the fire waits at the hearth.
- **Entry.** The fire rises into a curtain of warm light, and the stream where the forest meets the plain surrounds the stationary visitor. The camera never moves. The ember crosses into the scene as the traders' fire or the camp lantern.
- **The story.** People and the ewe are shapes of firelight; they have no faces, so no likeness is drawn. They walk in along paths over the ground when they appear, go where the story sends them (Wambui and Naserian kneel at the hide to trade; Njeri goes to Naisula's side), and walk away when they part. Each era has a hand moment: a gourd held out to an open palm (with a nearby button), and then touching the water, the trading hide or the rails. Lines after it differ by what the visitor did. Without input, a passive default plays, and the fire never says the visitor chose it.
- **Questions.** A panel by the right hand offers authored questions, including one about whatever the visitor has been looking at. An answer interrupts and then resumes the story from a safe boundary. Head direction is recorded only as a signal, never as consent or eye tracking.
- **Return.** The world folds back through the light, and the keepsake (a bead or a seed bundle) rests on the right hearth stone. **Keep this visit**, Begin again or Leave.
- **Kept visits.** Only an explicit Keep saves a visit, as one local file. The welcome back then offers the kept visit to replay exactly, follow to the same water today, start a new story, or forget it, after a confirmation. Today recalls only what was kept.
- **Interruption.** Pause (button, headset removal or the system menu) stops speech and freezes every timer. Resume restarts the line from its start without repeating its actions. **Return to the fire** leaves the story at any point and is never recorded as finishing it.
- **Settings.** Caption size, reduced motion (a short dim dissolve with no rising fire), ambience level (full, low or off), recenter, and in development builds the fire comparison below.

Each cue is logged as `[Sankofa] <cue> at <visit time>`, and the visit journal is logged when the visitor reaches the closing. Read them with `adb logcat -s Unity` on a headset.

## How the hearth is made

The hearth's geometry, lighting and sound are generated from code, with no AI-generated media. Its surfaces use four scanned CC0 materials from Poly Haven (rock, burned ground, dry ground, bark; see the [asset register](../docs/asset-register.md)), projected triplanar on stones, from above on the ground (blended from dry earth to burned ground by a per-vertex burn amount around the fire), and along the grain on wood, with a large-scale procedural variation to hide tiling. The pieces: noise-displaced stones (sooted on their fire-facing sides) and pebbles, irregular logs with bark grain, a laid and leaning fire of five flame tongues on coals whose cracks glow and pulse with the flames, seats and twigs, terrain with an ash ring and distant hills, grass that sways, tree silhouettes, and a night sky with stars and a moon. Sparks burst in time with the synthesised crackle; thin smoke and a halo stand in for volumetrics and bloom.

Lighting is two-toned: the warm fire, whose centre wanders a few centimetres, and faint cool moonlight with rim light and low mist over the distance. Soft fire shadows, moon shadows and ambient occlusion are ray-traced once by `SankofaBake` into vertices, because neither the fire nor the moon moves relative to the hearth. Every shader ends with a shared grade (`SankofaGrade.cginc`) in place of post-processing: a filmic tone curve so the flame rolls off rather than clipping, slight desaturation, a multiplicative split tone, and dithering against banding.

Static pieces are combined per material, about ten draw calls and 173,000 triangles in total, of which the distant tree canopies are 66,000 and the first to cut if profiling requires.

## How the story scenes are made

The three scenes in [the scene scope](../docs/content/enkare-nairobi/scenes.md) are generated the same way, in `SankofaWaterScenes`.

- **Shared ground.** A stream crosses about 2.4 m ahead, in a narrow channel whose banks hide the water's edges. The forest rises on the left and the plain falls away on the right.
- **Before the railway.** A spring spills over a rock within reach. The traders' fire lights the scene, with a hide on a flat rock between the visitor and the stream.
- **When the railway came.** The bank is trampled and cut. Bell tents and timber stand across the stream, an embankment runs beyond, and a crib of sleepers and rails is within reach.
- **Today.** The river runs between a raised garden bed, a stall with a charcoal *jiko*, a painted gate, streetlights and a city whose windows come from world position in the City shader.

People are additive ember-and-smoke figures (`EmberFigure.shader`), single continuous silhouettes so no part doubles in brightness. `FigureMotion` walks them along paths baked from the terrain, with a gentle step, and the shader folds the same silhouette into a kneel. The story moves a figure with a `move` action to an object's approach point; that point says whether one stands or kneels there. Water uses an opaque `Water.shader`: there is no transparency cost, and it reflects the sky and glints in the scene's warm light and moonlight. Each scene has its own synthesised ambience (`StoryAmbience`): stream, insects, birds, wind, a distant sheep bell, the traders' small fire, hammers on iron, canvas, city traffic, and voices as a wordless murmur, built from no words so that no language is represented before its speakers have been asked. The ewe bleats now and then (`ObjectSound`). It ducks under the narrator like the night at the hearth.

Captions and control labels use TextMeshPro's signed-distance-field type in Atkinson Hyperlegible, a typeface designed for low-vision readability (LiberationSans is the fallback for missing glyphs), which stays crisp at any distance in a headset. Captions sit on a soft dark backing fitted to the line, with a thin outline for contrast against flame and sky; a medium caption line subtends at least one degree from the seat, which the PlayMode test checks. The control panels are firelit wooden plaques with warm labels of one consistent size.

The night is synthesised like the crackle: four crickets placed around the clearing, a faint distant chorus and gusting wind with leaf rustle, each a seamless loop of a different length. The ambience ducks to about half while the narrator speaks and follows the visitor's ambience setting.

## Fire presence comparison

The stress test's T3 asks whether a directed fire feels more responsive than a simple one. In development builds the settings panel's **Fire** button switches between the directed fire (state cues, lean while listening, breathing with speech) and a steady fire with the same narration. Use it only with recorded narration and counterbalanced order. Caption-only lines drive the fire from a synthetic speech rhythm, which is not a fair comparison.

## Running in the Meta XR Simulator

Without a headset, the hearth runs in Play mode against the [Meta XR Simulator](https://developers.meta.com/horizon/documentation/unity/xrsim-intro/), installed at `/Applications/MetaXRSimulator.app`. Use **Sankofa > Play Hearth in XR Simulator**, or with the editor closed:

```sh
"$UNITY" -projectPath "$PWD/unity" -executeMethod Sankofa.EditorTools.SankofaSimulator.PlayHearth
```

The simulator starts with controllers: aim with the mouse and click to pull the trigger at a panel. Switch the simulated hands to hand input to try the open palm, touch and pinch. The simulator exercises flow, visuals and wiring; it is not evidence of hand-tracking reliability, comfort, sound or Quest performance.

## Running on a headset

Installing a development build needs a Quest in developer mode, which needs a Meta developer account set up by the owner. Unity's Android support includes `adb` at `/Applications/Unity/Hub/Editor/6000.3.25f1/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb` if it is not on your path.

```sh
adb install -r artifacts/Sankofa.apk
```

Sit down before launching: the hearth is placed in front of where your head is when tracking settles, and **Recenter** places it again.

## Implemented but unverified

Unit, EditMode, PlayMode and build checks establish software behaviour only. Still unknown until device and participant evidence exists: whether the palm, touch and question gestures work reliably with real hand tracking; the narration's pronunciation and pacing on a headset; the ember figures' legibility and comfort at close range; panel, offer and keepsake reach and comfort for different bodies; the fire's look and frame cost; comfort of the curtain transition; caption legibility; the procedural crackle's sound; and spatial voice placement (Unity's built-in panning, not an HRTF spatializer).

Known review items before release:

- Meta's setup tool adds a telemetry project identifier to the Android manifest and lists every Quest model as supported. Disclose or remove the identifier as the privacy notice requires, and list only devices with recorded evidence.
- Unity's performance-test package (a dependency of `com.unity.collections`) writes build metadata into every player build's Resources by design: Unity version, player settings and the package list, with no paths, names or credentials (checked in the October 1 APK). Decide whether to strip it from release builds.
